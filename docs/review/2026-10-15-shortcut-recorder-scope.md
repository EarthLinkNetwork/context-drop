# ショートカットの記録・最前面ショートカット・設定画面の整理と自動保存 (v0.1.9) — review scope

## 保証すること
- **Always on Top のグローバルショートカット**（既定 `CommandOrControl+Shift+8`）。押すたびに最前面を ON/OFF し、トレイのチェック表示と設定画面と同じ保存値を使う。
- **3 つのショートカット（Capture・表示/非表示・Always on Top）は、どれも同じ操作で設定できる**:
  - 「Change」を押してから、使いたいキーの組み合わせを押すと、その組み合わせが保存され、すぐ有効になる。文字列を手で打つ必要はない。
  - 記録中もグローバルショートカットは**登録したまま**にする（外して付け直さない＝再登録の失敗やスレッド間の待ち合わせが起きない）。記録中に登録済みのショートカットが押されたら、その動作（Capture の切り替えなど）はせず、押されたキーとして画面に渡す（`cd:shortcut-pressed`）。それ以外のキーは WebView の keydown で受ける。
  - 記録中かどうかはバックエンドが持つ（`begin_recording`／`end_recording`、期限 20 秒で自動的に終わる）。ウィンドウからフォーカスが外れたとき・隠したときは記録を終え、画面へ `cd:recording-ended` を送る。画面側もウィンドウの blur で記録をやめる。だから画面だけが「記録中」のまま残ることはない。
  - keydown の修飾キー単体・キーリピート・IME 変換中は無視し、記録中はすべての keydown/keyup で既定の動作を止める（Change ボタンの再押下や Tab での移動を起こさない）。
  - Cmd / Ctrl / Option(Alt) のどれかを含む組み合わせだけを受け付ける（Windows/Linux では Ctrl か Alt。Win キーだけでは受け付けない）。修飾キーが無い Enter・Tab・文字キーや、Shift だけの組み合わせは受け付けず、記録を続けながら理由を表示する。Esc（修飾キーなし）は記録を取り消す。
  - 記録できるのは一度に 1 行だけ（記録中はほかの行の Change / Clear / Reset を無効にする）。画面の再描画（1.5 秒ごとの再取得など）は記録に影響しない（記録の処理は「記録中かどうか」だけに依存し、ほかの値は最新のものを参照する）。画面側は再描画があっても 19 秒で記録を終える。バックエンドも 20 秒の時点で自分から記録を終え、`cd:recording-ended` を送る（キーが押されるのを待たない）。Shortcuts タブや Settings を離れたときも記録を終える。記録の開始時点でウィンドウにフォーカスが無ければ（Change の直後に別アプリへ移った）、バックエンドはすぐ記録を終える。
  - キー名と修飾キー名の対応は、global-hotkey 0.8.0 の `parse_hotkey`／`parse_key` と同じ表を画面側に持つ。そのため、同じキーの別の書き方（`CommandOrCtrl` と `CommandOrControl`、`Option` と `Alt`、`-` と `Minus`、`Num1` と `Numpad1`、`Esc` と `Escape`、`NumPlus` と `NumpadAdd` など）は、画面側の重複判定でも同じキーとして扱う。文字・数字・記号・矢印・F1〜F20・Space・Enter・Tab・Backspace・Delete・Home/End/PageUp/PageDown・テンキー（Enter と演算キーを含む）・Esc は、修飾キーと組み合わせて記録できる（修飾キーなしの Esc は取り消し）。次のキーは記録の対象外とする: global-hotkey に macOS のキーコードが無いもの（F21〜F24、Pause、ScrollLock）、Mac のキーボードで別の意味を持つかキーが無いもの（NumLock＝テンキーの Clear、Insert、PrintScreen）、メディア・音量キー、修飾キーとして働く CapsLock。
  - 「Clear」で OFF（空）にする。「Reset」で既定値に戻す。OFF の状態は「Off」と表示する。
  - アプリ内のほかのショートカットと同じ組み合わせは受け付けず、どれと重なるかを表示する（Reset で既定値に戻すときも同じ）。**最終的な判定はバックエンドが保存の時点で行う**（lifecycle ロックの中で、保存しようとする値と保存済みのほかの値を `Shortcut::id()` で比べ、重なれば保存せずにエラーを返し、画面に理由を出す）。画面側の判定はすぐ知らせるための補助で、前の保存が失敗した場合などに外れても、重複が保存されることはない。バックエンドでも `Shortcut::id()` で重なりを判定し、優先順は Capture → 表示/非表示 → Always on Top（後のものを「重複」として登録しない）。v0.1.8 から上げたときに新しい既定値 `Cmd+Shift+8` が利用者の値と重なる場合は、Always on Top のショートカットを OFF として入れる（「重複」の警告を出さない。一度だけ・設定キーがまだ無いときだけ）。
  - Capture のショートカットも OFF にできる（v0.1.8 までは空にすると既定値に戻していた）。v0.1.8 以前の DB で空の値は保存されていないので、既存の利用者の設定は変わらない。
- **設定画面をタブに分ける**: Capture | Settings の Settings の中を「Shortcuts」「Window」「Claude Code」「Advanced」に分ける。Packet TTL・サイズ上限・自動クリーンアップ・データフォルダ・プライバシーは Advanced に入れる。「Open Setup」のバナーは Claude Code タブを開く。
- **設定はすべて自動保存**（「Save Settings」ボタンを無くす）: ショートカットは記録が終わった時点、チェックボックス・選択肢は変えた時点、数値は入力欄から離れたとき（Enter を含む）に保存する。数値が不正（空・0 以下・数でない）なら保存せず、保存済みの値に戻す。保存した項目の横に「Saved」を短く出す。
  - 保存は**項目単位**（`update_settings(patch)`）。バックエンドが lifecycle ロックの中で DB から読み、その項目だけを当て、sanitize して保存する。だからトレイやショートカットでの最前面の切り替えなど、ほかの経路の変更を巻き戻さない。画面からの保存は 1 本の列で順に送る。
  - チェックボックスは押した値をすぐ表示し、続けて押すと逆の値を送る（同じ値を 2 回送らない）。数値欄は編集中だけ入力した文字を表示し、それ以外は常に保存済みの値を表示する（バックエンドが丸めた値を、保存したかのように残さない）。
  - 画面の表示と判定（数値が変わったか・ほかのショートカットと重なるか・チェックの状態）は、すべて「保存済みの値＋まだ保存が終わっていない変更」（＝利用者が最後に選んだ値）に対して行う。だから、前の保存の完了を待たずに値を戻したり、別の行に同じキーを入れたりしても、正しく保存または拒否される。
  - 最前面の切り替えは、トレイ・ショートカット・設定画面のどこからでもメインスレッドで順に行う（保存と、ウィンドウ・トレイへの反映の順序が入れ替わらない）。
  - 保存中もフォーム全体を無効にしない（アプリ全体の busy を使わない）。失敗したときは、その画面に理由を出す。
- 全体の警告バナーは、状態が failed・duplicate・invalid のショートカットがあるときだけ出す（OFF のときは出さない）。
- 最前面の切り替えが失敗したとき、トレイから呼ばれた場合だけチェック表示の反転（macOS が自動で反転させた分）を戻す。ショートカットから呼ばれた場合は反転させない。
- 3 つのショートカットの登録と、押したときの振り分けを、純粋関数（`context_drop_core::shortcuts`）に切り出してテストする。重なった値の拒否、空の扱い、振り分け（登録できたものの id だけで振り分ける）が対象。
- 版を 0.1.9 にそろえる（tauri.conf / plugin / marketplace / CHANGELOG）。

## 保証しないこと
- macOS のシステムのショートカット（`com.apple.symbolichotkeys`）やほかのアプリのショートカットと重なっているかを、記録の時点で調べること（登録に失敗したときは警告を出す。登録が成功扱いになる重なりは検出できない）。
- 修飾キーを含まない単独キー（F キーなど）をグローバルショートカットにすること。
- macOS でアプリのメニューや OS が先に受け取るキーの記録: Cmd+Q / Cmd+W / Cmd+H / Cmd+M と編集用の Cmd+C / V / X / A / Z（アプリの既定メニュー。入力欄のコピー・貼り付けに要るので外さない）、Cmd+Tab・Cmd+Space・Cmd+Shift+3/4/5 など（OS）。これらは画面に届かないか、メニューの動作になる。
- ほかのアプリがグローバルショートカットとして先に取っている組み合わせの記録（そのキーは画面に届かない）。
- 記録の対象外のキー（global-hotkey が読めない JIS の ¥・かな/英数と、上の「対象外」のキー）。記録時に「使えないキー」と表示する。

## 前提
- グローバルショートカットの登録・解除は、メインスレッドで動く処理（起動処理と同期コマンドの `update_settings`）からだけ行う（別スレッドからロックを持ったまま呼ばない）。
- Tauri の global-shortcut プラグイン（global-hotkey 0.8.0）が読めるキー名（`KeyA`/`A`、`Digit0`/`0`、`F1`…、`ArrowUp`、`Space`、`Enter`、記号の名前など）に、`KeyboardEvent.code` から変換する。修飾キーは macOS では Cmd → `CommandOrControl`・Control → `Control`、Windows/Linux では Ctrl → `CommandOrControl`・Win → `Super`。
- v0.1.8 のウィンドウ配置・表示ショートカット・最前面の挙動はそのまま（docs/review/2026-10-15-window-placement-scope.md）。

## 受け入れる限界
- Windows の AltGr（Ctrl+Alt として届く）で記号を打つと、Ctrl+Alt の組み合わせとして記録されることがある。
- 同じ項目を 2 つの経路（設定画面とトレイ）からほぼ同時に変えた場合は、後から保存した方が残る（別の項目は巻き戻らない）。
- 記録中の表示はキーボードのレイアウトに関係なく、物理的なキーの位置（`KeyboardEvent.code`）で決まる（US 配列以外では、表示の記号と実際の刻印が違うことがある）。
